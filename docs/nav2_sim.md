# Nav2 Simulation And Bag Replay

This document is for empty-world Nav2 checks that do not fly a real UAV. Use it to verify MAV1 topics, coordinate frames, `/odom`, TF, `/plan`, and `/cmd_vel`.

Bag replay is open-loop: the recorded trajectory will not respond to the `/cmd_vel` generated by Nav2. A later controller/progress abort is normal during bag replay.

## Coordinate Frames

PX4 publishes local odometry in NED. Nav2 expects ROS ENU through `/odom` and TF.

The converter applies:

```text
ROS ENU x = PX4 NED y
ROS ENU y = PX4 NED x
ROS ENU z = -PX4 NED z
```

Nav2 requires:

```text
map -> odom -> base_link
```

In this test, `map -> odom` is static identity and `odom -> base_link` is generated from `/MAV1/fmu/out/vehicle_odometry`.

## A. Topic / TF / Axis Check

Terminal 1:

```bash
cd /home/zhg/ncrl_mqtt/catkin_ws
source install/setup.bash
ros2 launch drone_nav2_apriltag mav1_nav2_topic_check_sim.launch.py
```

Terminal 2, replay the local MAV1 test bag:

```bash
ros2 bag play \
  /home/zhg/ncrl_mqtt/catkin_ws/src/drone_nav2_apriltag/bag/mav1_nav2_odometry_test \
  --clock \
  --rate 0.5 \
  --topics \
  /MAV1/fmu/out/vehicle_odometry \
  /MAV1/fmu/out/vehicle_local_position_v1 \
  /MAV1/fmu/out/estimator_status_flags \
  /MAV1/fmu/out/vehicle_status_v1 \
  /vrpn_mocap/MAV1/pose_reliable
```

Expected output:

```text
Nav2 readiness: READY
[topic] vehicle_odometry: ok
[topic] vehicle_local_position_v1: ok
[topic] mocap_pose: ok
[tf] odom -> base_link: ok
[tf] map -> base_link: ok
```

For the coordinate-axis bag, `heading_good_for_control` and `cs_yaw_align` may be false. That is acceptable for this test. Use the bag to confirm the rectangle path appears in the expected direction in RViz.

Optional RViz:

```bash

```

## B. Nav2 Planning Check

Terminal 1:

```bash
cd /home/zhg/ncrl_mqtt/catkin_ws
source install/setup.bash
ros2 launch drone_nav2_apriltag nav2_empty_world.launch.py use_sim_time:=true
```

Terminal 2:

```bash
ros2 bag play \
  /home/zhg/ncrl_mqtt/catkin_ws/src/drone_nav2_apriltag/bag/mav1_nav2_odometry_test \
  --clock \
  --rate 0.5 \
  --topics /MAV1/fmu/out/vehicle_odometry
```

Terminal 3, send a test goal inside the fake map:

```bash
ros2 action send_goal /navigate_to_pose nav2_msgs/action/NavigateToPose \
"{pose: {header: {frame_id: map}, pose: {position: {x: 1.0, y: 2.0, z: 0.0}, orientation: {w: 1.0}}}}"
```

Check outputs:

```bash
ros2 topic echo /plan --once
ros2 topic echo /cmd_vel
```

Success for this stage means:

```text
/odom exists
odom -> base_link exists
map -> base_link exists
Nav2 accepts the goal
/plan is published
/cmd_vel is published
```

It is normal for Nav2 to abort later during bag replay because the bag trajectory is pre-recorded and will not follow the new `/cmd_vel`.

## C. Empty Gazebo World

For Gazebo-only empty-world checks, start PX4/Gazebo with:

```bash
cd /home/zhg/ncrl_mqtt/catkin_ws/src/drone_nav2_apriltag/scripts
PX4_GZ_WORLD=empty_nav2 DRONES=1 ./start_arena_sitl.sh
```

Start XRCE-DDS separately:

```bash
MicroXRCEAgent udp4 -p 8888
```

Then use either the topic-check launch or the real manual flight launch depending on whether you want only topic validation or closed-loop motion.
